# 视觉工程实现细则

开始本类任务前，先完整读取根目录 `AGENTS.md`。若实现用于研究实验，还要读取 `vision-research.md`；若需要测量或回放，还要读取 `experiments-and-validation.md`。

## 修改前

1. 检查 `git status`、相关调用方、配置读取路径和已有测试。
2. 写清接口契约：坐标系、单位、时间戳语义、输入范围、空值/丢帧行为和线程所有权。
3. 确认任务 `implementation_mode`。`proposal` 只允许写研究项目目录；`workspace-change` 才允许修改源码。
4. 先保存可复现基线。环境不完整时，不把依赖缺失误判为代码失败。

## C++ 与实时路径

- 使用项目的 C++17 设置、现有命名空间和头文件保护风格。
- 优先值语义、RAII 和明确所有权；避免裸拥有指针和隐式共享可变状态。
- 图像循环、推理、跟踪和控制命令路径中避免无界容器增长、磁盘阻塞、频繁堆分配和高频格式化日志。
- 多线程改动必须说明生产者/消费者、队列容量、丢弃策略、关闭顺序和时间戳来源。
- 时差使用 `std::chrono::steady_clock`；只有对外展示的墙钟时间使用系统时钟。
- 数值代码要处理 `dt <= 0`、NaN/Inf、矩阵病态、角度环绕、零长度向量和协方差非正定风险。
- 不在没有量化证据时“顺手优化”或大规模重构。

## 配置与兼容性

- 新 YAML 项必须记录类型、单位、范围、默认值、适用机器人和缺失时行为。
- 不静默改变已有参数含义。需要迁移时同时更新所有 `configs/*.yaml`、示例和文档。
- 模型输入尺寸、颜色通道、归一化、类别顺序和输出布局必须与导出模型一致。
- 标定矩阵和外参改动要记录对应相机、镜头、分辨率和重投影结果，不推广到其他机器人。

## 分层验证

按当前环境能支持的最高层级执行：

1. 格式、语法、配置解析和静态检查；
2. 受影响模块的单元测试；
3. 完整 CMake 构建；
4. 固定录像/日志的离线回放；
5. 台架；
6. 实车。

新增缺陷修复应提供回归测试或最小复现。若测试程序需要相机、CAN 或发射机构，不自动运行；列出研究者可在安全条件下执行的命令和预期现象。

## 审查清单

- 数据结构或函数签名是否破坏所有调用方？
- 坐标系、单位、符号和角度环绕是否一致？
- 时间同步和预测延迟是否重复计算或漏算？
- 丢检、重识别、装甲切换、目标跳变和程序退出是否安全？
- 调试宏关闭时是否仍能构建？
- CPU/GPU、amd64/arm64、ROS2 可选环境是否受到无意影响？
- 日志是否包含大图、设备信息或其他不应提交的数据？
- 是否保留明确回退路径？

## 交付

给出改动摘要、关键接口决定、实际执行的检查、未执行检查及原因、性能证据等级和需要研究者完成的硬件步骤。Agent 不因本地构建通过而宣布实车有效。
