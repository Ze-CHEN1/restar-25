# 实验与验收细则

开始本类任务前，先完整读取根目录 `AGENTS.md`。

## 实验卡片

每次实验开始前在 `experiment-ledger.md` 写明：

- 实验 ID、日期和负责人；
- 要检验的单一假设；
- 基线提交/分支、候选提交/工作区差异；
- 数据或录像 ID、场景切片、许可与完整性哈希（适用时）；
- 配置文件及覆盖项；
- 构建和运行命令、随机种子、预热轮数和重复次数；
- 主指标、护栏指标、验收阈值和停止条件；
- 平台、CPU/GPU、相机、分辨率和软件版本；
- 原始输出与失败样本路径。

实验完成后记录原始数值、置信区间或重复波动、异常样本、结论、证据等级和是否需要复验。不能只粘贴结论。

## 推荐指标

| 模块 | 主指标 | 必须同时观察 |
|---|---|---|
| 装甲/能量机关检测 | precision、recall、F1/mAP、角点误差 | 距离/颜色/曝光/模糊切片，预处理与后处理延迟 |
| 分类 | 每类 precision/recall、混淆矩阵 | 低置信度和拒识率 |
| 位姿与标定 | 重投影误差、位置/姿态误差 | 距离、视角、PnP 解分支、外参漂移 |
| 跟踪 | 丢失率、重捕获时间、ID/装甲切换错误 | 创轨时间、发散率、不同转速 |
| 预测 | 不同预测时域的角度/位置误差 | 加减速、装甲切换、时间偏移敏感性 |
| 规划与开火 | 轨迹误差、射击窗口、命中率、击杀时间 | 射频、距离、延迟、云台饱和 |
| 端到端 | 命令误差、成功率 | P50/P95/P99 延迟、抖动、丢帧、CPU/GPU/内存 |

指标定义和单位必须写进任务，尤其是角点误差的匹配规则、命中率分母、击杀时间起止点和延迟的时间戳边界。

## 数据切分与可复现性

- 按录像序列、场次或采集批次切分，避免相邻帧泄漏到训练和测试两侧。
- 冻结基线与报告集。探索集可用于调参，报告集只在里程碑验收时运行。
- 基线和候选使用相同输入、线程设置、预热和测量窗口。
- 性能测试至少重复三次；若波动大，先找系统噪声来源。
- 保存机器可读结果和简短人工解读。大文件留在获批的外部存储，只在仓库记录 ID、哈希和取得方式。

## 离线回放

离线回放优先于硬件测试。确认录像中的图像、时间戳、四元数和电控状态语义与在线路径一致。若回放绕过了相机传输、线程排队或通信，报告必须明确它无法验证这些延迟。

比较算法时同时保存失败样本清单，而不是只导出最佳可视化。任何人工删帧、裁剪或重新标注都要留记录。

## 台架与实车闸门

Agent 不启动需要真实相机、串口、CAN、云台或发射机构的命令。准备这类验证时，先输出：

1. 风险和受影响机构；
2. 供电、限位、急停、场地、护目和供弹检查；
3. 精确命令、配置和预期输出；
4. 中止条件和回退版本；
5. 需要记录的日志与视频。

只有研究者明确回报结果后，才能登记 `hardware-validated`；比赛证据同理。

## 结论规则

- 结果未达到主指标：拒绝或修改假设，不修改验收阈值来制造成功。
- 主指标提升但护栏退化：保持 `researching`，定位权衡，不宣布完成。
- 只在离线门槛全部通过时使用 `candidate-complete`。
- 无数据时使用 `needs-data`；需台架/实车确认时使用 `needs-hardware-validation`。
- 研究者确认是否接受改动，并最终设置 `accepted`。
