# 视觉算法研究细则

开始本类任务前，先完整读取根目录 `AGENTS.md`。

## 1. 把问题变成可检验任务

先从 `research/tasks/<slug>/task.md` 和冻结快照提取：

- 目标行为与不允许退化的行为；
- 当前基线的代码、模型、配置和数据；
- 自变量、控制变量、输出指标和验收阈值；
- 运行平台、延迟预算、内存预算和部署限制；
- 哪些结论需要离线数据、台架或实车才能回答。

若没有基线数字，第一项研究产物应是基线测量方案。不得先选方案再倒推对其有利的指标。

## 2. 建立误差预算

端到端自瞄问题应至少审计以下来源，并区分偏差、方差和延迟：

1. 成像：曝光、运动模糊、畸变、ROI、图像传输时间；
2. 识别：漏检、误检、角点误差、类别置信度与域偏移；
3. 几何：内参、畸变、装甲板尺寸、PnP 多解、外参和坐标系约定；
4. 状态估计：数据关联、初始化、过程/测量噪声、跳变、短时丢失和发散；
5. 预测与弹道：时间同步、速度模型、飞行时间、空气阻力和参数漂移；
6. 规划与控制接口：轨迹可跟随性、命令延迟、饱和、开火延迟和通信抖动。

不要用下游参数掩盖上游系统误差。发现统一偏差时，先判断它来自标定、时间同步、坐标变换、弹道还是机械零偏。

## 3. 候选方案与路线选择

在 `hypothesis-ledger.md` 至少登记两个核心机制不同的方案。例如检测问题可以比较数据/训练改进、后处理/几何约束和模型结构；跟踪问题可以比较观测建模、运动模型和数据关联。

每条方案记录：

- 机制解释；
- 预期改善的误差项；
- 可能退化的场景；
- 最小实验与证伪条件；
- 实现代价、实时性风险和回退方法；
- 当前状态：`proposed`、`testing`、`supported`、`rejected` 或 `parked`。

优先推进能最大幅度区分候选机制、且成本最低的实验。只有换参数而没有改变机制的多个版本仍算同一路线。

## 4. 外部资料与新颖性

联网模式下优先阅读原论文、官方实现、数据集说明和上游库文档。对关键结论记录稳定链接、版本/提交、适用条件、许可和与本项目的接口差异。

博客、论坛和其他战队代码可提供线索，但不能代替原始定义或本项目复现。没有完成检索前，不声称“首次”“最优”“已解决”或“业内通用”。外部代码进入仓库前先审查许可证，不直接复制不兼容代码。

离线模式不得联网；把需要核查的外部事实写为待办，不凭记忆伪造引用。

## 5. 研究回合

每一回合只承诺一个清晰交付，例如：冻结基线、关闭一个误差来源、完成一个消融、拒绝一条路线或形成可审查补丁。建议顺序：

1. 读取当前台账和最近实验，找出最小未闭合问题；
2. 写出本轮假设和成功/失败判据；
3. 执行最小实验或静态分析；
4. 对结果做分层切片和失败样本检查；
5. 更新所有受影响台账，保存命令和产物路径；
6. 指定下一轮唯一优先动作和备选动作。

同一方案在同一阻塞上失败两次后，不机械重复。改变观测、数据切片、核心模型或实验设计，或者将其标为 `rejected` 并转向其他路线。

## 6. 常见研究陷阱

- 只看总平均，掩盖高速旋转、远距离或遮挡场景退化；
- 用测试集调阈值后仍把它称为独立测试；
- 同时改变模型、配置和数据，无法归因；
- 只测推理核耗时，忽略预处理、拷贝、排队和后处理；
- 录像时间戳与真实采集时刻定义不一致；
- 用重投影误差低推断世界坐标或击打误差一定低；
- 只记录成功参数，不记录搜索空间和失败配置；
- 在单机器人、单光照上的结果泛化到比赛环境。

## 7. 回合输出

至少更新：

- `progress.md`：日期、目标、动作、结果、阻塞、下一步；
- `hypothesis-ledger.md`：方案状态与证伪证据；
- `experiment-ledger.md`：数据、配置、命令、指标和产物；
- `decisions.md`：采用/拒绝方案及原因；
- `README.md`：当前状态、最高证据等级和最小缺口。
